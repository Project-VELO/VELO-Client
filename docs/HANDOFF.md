## 작업할 때 알아두면 좋은 것

* **플레이 모드 검증은 `PersistentScene`을 열어 둔 상태에서** 시작해야 합니다. 아니면
  `SceneTransitionManager.Instance`가 null이라 서브 씬 전환이 조용히 실패합니다.
* **프리팹 편집은 `PrefabUtility.LoadPrefabContents` → `SerializedObject` → `SaveAsPrefabAsset`** 경로가
  MCP의 범용 프리팹 도구보다 훨씬 안정적입니다.
* **MCP `execute_code`는 CodeDom(C# 6)** 으로 돌아갑니다. `using` 지시문을 쓸 수 없어 전부 정규화된
  이름으로 적어야 하고, 확장 메서드(`SetUpdate` 등)는 `TweenSettingsExtensions.SetUpdate(t, true)`처럼
  정적 호출로 풀어써야 합니다.
* **리듬게임을 손으로 클리어하지 않고 결과를 흘려보내려면** `LiveResultProcessor.ApplyResult(result)`에
  직접 `LiveResultData`를 주입하십시오. 전 필드가 public setter이고, 이 함수 하나가 기획서 3-K-3
  순서 전체(최초클리어 판정 → 보상 → 최고기록 → 스케줄완료 → 저장)를 수행합니다. **판정·입력·오디오
  계층만 우회하고 나머지는 실전 코드를 그대로 통과**하므로 로직 검증에 쓸 수 있습니다.
  반면 디버그 창의 "완료 처리"는 `ForceCompleteSchedule`이라 `ScheduleCompletionRule`을 통째로
  건너뜁니다 — **LIVE→스케줄 연결 검증에는 쓰면 안 됩니다.**
* **한글과 ★을 함께 쓰는 TMP 텍스트는 `GowunBatang` 계열 폰트**를 써야 합니다.
  `LiberationSans SDF`와 CleanFlatUI의 `DemoFont*`는 둘 다 지원하지 않습니다.
* **커밋에 `Co-Authored-By` 트레일러를 넣지 않습니다.** GitHub 작성자 자리에 모델명이 끼어듭니다.
* **PR은 직접 만들지 않습니다.** 푸시하면 워크플로가 자동으로 생성합니다.
